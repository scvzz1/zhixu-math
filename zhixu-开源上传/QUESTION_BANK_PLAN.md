# 题库与题目更新计划

本计划只管理数学题目数据及其学术质量，不负责页面布局、按钮行为或学习记录功能。题目编写和审核必须遵守 [QUESTION_AUTHORING_STANDARD.md](QUESTION_AUTHORING_STANDARD.md)。

## 目标

建立经过复核、可分类、可持续扩充的考研高数题库，并让题目数据与页面代码分开维护。

## 工作范围

- 新增、改写、删除题目内容。
- 核对题干、选项、答案、提示、解析和知识点。
- 维护科目适用范围、章节、细分考点、题型、难度、预计用时、前置知识。
- 记录原创/改编来源、授权情况和审核状态。
- 按题目规范检查数学公式和字段内容。

不在本计划范围内：练习页面样式、导航、答题流程、错题交互、分析算法、账号、存储和其他产品功能。需要这些改动时，记录到 [UI_FEATURE_PLAN.md](UI_FEATURE_PLAN.md)。

## 阶段与交付

### 阶段一：清理并复核现有示例题

1. 建立当前题目清单，给每题分配稳定 ID，避免题目排序变化后历史记录指向错误题目。
2. 逐题核对题干、选项、答案索引、提示、分步解析、知识点和难度。
3. 复核所有数学结论，修复选项重复、答案冲突、条件遗漏及格式错误。
4. 标注来源和审核状态；未复核的内容不得标为已审核。

**交付：** 一份题目清单和一组已审核的现有示例题。

### 阶段二：分离题目数据

1. 从 `index.html` 的页面脚本中迁出题目数据，页面通过统一的数据接口读取题目。
2. 选择机器可读、便于人工审阅的独立格式，避免题库修改需要编辑页面逻辑。当前采用同目录 `question-bank.js` 导出数据对象，以支持项目直接使用 `file://` 打开；改用本地服务器后可再评估拆为纯 JSON 并通过数据加载接口读取。
3. 明确必填字段、允许值、ID 规则、版本和兼容策略。
4. 由程序工作线负责读取与展示；本阶段只定义数据契约，不在题库计划里重做页面。

**交付：** 独立题库文件和字段说明；页面可消费该数据格式。

**本阶段当前实现：** 现有 9 道示例题已迁到 `question-bank.js`，每题有稳定 ID；`index.html` 以同目录经典脚本方式加载，兼容直接打开本地 HTML。页面校验题库版本、ID 唯一性、专题索引、选项数量和答案索引，并把旧版按数组位置保存的作答/错题引用迁移到稳定 ID。网页侧边栏现有“题库”入口，支持搜索、按专题和难度筛选、展开查看题目答案与解析，以及直接开始练习。JSON 化及完整元数据字段仍可在后续单独推进。

**本次题库扩充记录（2026-10-11）：** 新增 7 道原创变式，覆盖根式极限、三角基本极限、切线、几何优化、分部积分、奇偶函数定积分和幂函数反常积分。题目对象附有 `source`（题型参考及非照抄声明）和 `review`（审核状态、日期）字段。参考资料为 OpenStax Calculus Volume 1 对应章节及 MIT OpenCourseWare 18.01SC 的公开练习；没有将商业练习册题目逐字复制进项目。新增内容按出题规范逐题复核了选项、答案索引、推导、定义域/端点条件和提示。

### 阶段三：扩充知识地图与题量

1. 按数学一、二、三区标注适用范围。
2. 按高数章节和细分知识点组织题目。
3. 逐步覆盖基础概念、典型方法、常见错误和综合应用。
4. 优先新增原创题及经过复核的原创变式题。

**交付：** 可按考试范围、章节、知识点、难度筛选的题库内容。

## 题库数据契约（建议）

```json
{
  "schemaVersion": 1,
  "id": "calc-limit-0001",
  "subject": ["math-1", "math-2", "math-3"],
  "chapter": "函数极限与连续",
  "knowledge": ["泰勒展开", "等价无穷小"],
  "type": "choice",
  "difficulty": "强化",
  "estimatedMinutes": 3,
  "prerequisites": [],
  "prompt": "题干",
  "options": ["A项", "B项", "C项", "D项"],
  "answerIndex": 1,
  "hint": "提示",
  "explanation": "分步解析",
  "source": { "kind": "原创", "reference": "", "license": "" },
  "review": { "status": "approved", "reviewedAt": "YYYY-MM-DD" }
}
```

数据格式确定后，`index.html` 中的 `topic` 数字索引和 `answer` 字段应通过迁移映射转换，不能直接假设历史记录可以无损兼容。稳定 `id` 应作为答题记录引用题目的依据。

**界面阶段二涉及的数据字段（2026-10-11，只扩展定义，未改动任何题目）：** 现有 100 题的 `type` 均为 `choice`。为支持填空与解答题作答，`type` 的允许值扩展为 `choice` / `fill` / `solve`，并新增可选字段：`answers`（`string[]`，`fill` 必填）为经审核的可接受答案列表，供界面做归一化等价形式比对；`answerText`（`string`，`solve` 可选）为参考答案，供用户对照自评；`answerNote`（`string`，`fill` 可选）为答题格式提示。程序侧已支持这些字段并在加载时校验（`fill` 缺少 `answers` 会明确报错）。**题库线待办：** 后续新增填空 / 解答题时，按《QUESTION_AUTHORING_STANDARD.md》补齐 `answers` 的等价形式清单（分数、小数、LaTeX 写法等）并经独立复核；本轮不新增、不修改任何题目内容。

## 与程序工作线的接口

- 题库工作线提供经过审核的数据和字段说明。
- 程序工作线实现数据加载、字段校验、筛选和展示。
- 字段增删或语义变化时，两份计划分别记录数据迁移和程序兼容任务。
- 页面上的排版缺陷报到程序计划；题干、选项或解析本身的错误报到本计划。

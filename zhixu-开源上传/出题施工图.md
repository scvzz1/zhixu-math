## 0. 这份表是什么

每一行 = 注册表里的一个知识点。它把「对齐考研掌握程度」从主观判断变成**逐行核对**：题写出后回看那一行，难度、用时、陷阱是否落在表内定的范围里，一眼可查。

它同时是**反向约束**：低要求知识点（大纲写"了解"）不该出综合计算题；高要求知识点（"掌握/会应用"）不该只出记忆题。

## 2. 定档规则与取值规范

### 2.1 两段式定档（避免"大纲措辞直接定档"的自相矛盾）

1. **实际档位由真题实证决定**——该知识点在 2010–2026 数一卷里的**实际考法与计算量**（步数、是否需分类讨论、是否为压轴）。
2. **大纲措辞只作约束**：
   - 「了解 / 会用」级 → **不得出综合计算大题**；
   - 「理解 / 掌握 / 会计算 / 会应用」级 → **不得只出记忆题**。
3. 两者冲突时**以真题为准**，并在表内注明依据。

### 2.2 取值规范

| 列 | 取值 | 说明 |
| --- | --- | --- |
| 难度 | **单值**：`基础` / `强化` / `综合` | 该知识点**建议主档**，不出现区间值 |
| 选填用时 | 整数分钟或 `—` | 选择 / 填空形态的目标用时；`—` = 本站不出该知识点的选填题 |
| 解答用时 | 整数分钟或 `—` | 解答大题形态的目标用时；`—` = 本站不出该知识点的解答大题 |
| 建议题型 | `choice` / `fill` / `solve` 的组合 | 该知识点**可出**的全部题型，与题目 `type` 字段一一对应；**不因本次拟出数量而省略** |
| 建议题量 | 整数 | **本次批次**拟出题数；不要求 ≥ 建议题型的种类数（该批从建议题型中挑若干种落地） |
| 现有题量 | 整数 | **本表产出时点**（2026-10-12）的实际题量快照；此后入库的补题不计入，最新题量以题库为准 |
| 真题命中 | `✔ 年份` / `◐` / `—` | 见 §2.3 |

### 2.3 「真题命中」列的可信度标记

| 标记 | 含义 |
| --- | --- |
| `✔ 年份` | 关键词在 2010–2026 数一真题**抽取文本**中命中（强证据） |
| `◐` | 抽取文本未命中，但按题型分布与考纲判为常考——**OCR 把公式转坏了，不是不考** |
| `—` | 真题中确属低频/未单独命题 |

> **局限**：① 2010–2019 是合并 OCR 卷，年份只能精确到「该十年内至少一次」；② 数学符号（∂、∫、Σ）在抽取文本中普遍丢失，故 `◐` 与 `—` **不能**当"不考"的结论。复跑脚本：`outputs/zt-scan.cjs`、`_drive/zt-scan-t67.cjs`。

### 2.4 一致性约束（可机检）

表 A 的三列相互牵制，任一处单独修改都要回查另两列。

| 编号 | 约束 | 性质 |
| --- | --- | --- |
| C1 | 「解答用时」非 `—` ⟺ 「建议题型」含 `solve` | 硬 |
| C2 | 「选填用时」非 `—` ⟺ 「建议题型」含 `choice` 或 `fill` | 硬 |
| C3 | 题库中该知识点**实际出现的题型** ⊆ 「建议题型」 | 硬 |
| W1 | 「建议题型」种类数 > 「建议题量」→ 仅提示该批需从中挑选，不算违规 | 提示 |
| W2 | 「建议题型」已列但库内 0 道 → 尚未补齐的题型缺口 | 提示 |

- **检查脚本**：`outputs/audit-blueprint.cjs`。把运行三件套（`index.html` + 两库）与本文档放同目录即可跑；硬约束违规时退出码为 1，提示项不影响退出码。
- **冲突时怎么改（配合 §2.1）**：「典型考法、目标用时」取自 2010–2026 真题实证，「建议题型」是规划列。两者冲突且真题实证支持该形态时，**改题型列、不改用时列**；若表 B 考法与真题都不支持某形态，则把对应用时列改为 `—`。
- **W2 清单的用途**：它就是**题型缺口**（该知识点建议题型里还没落地的形态），是后续补题的规范依据，而不是判断题。

## 6. 关键结论（从 t6/t7 试点得出，仍适用）

### 6.1 一道题只能挂一个知识点（硬约束）

`question-bank.js` 的 `q.kpId` 取 `knowledgeTags` 中**第一个**能命中注册表的标签，是**单值**；界面 `kpKey(q)` 直接用它聚合。

> **后果**：不能用"一题挂两个知识点"压缩题量——被让出的知识点会永远显示「零作答 / 待诊断」。**要让 N 个知识点进入诊断，就需要 N 道题。**

（若要压缩，需把 `kpId` 改成 `kpIds` 数组并同步改界面聚合——属跨题库线+界面线的改动。）

### 6.2 加题时必须同批处理的 `empty` 标记

# 考研高数题目编写规范

本规范只适用于本项目新增、改写和审核的题目数据，不负责页面布局、交互行为或通用界面文案。题目进入题库前，必须逐项符合本规范；发现数学错误、歧义或公式格式问题时，先修正并复核，再加入题库。界面和功能约定见 [UI_FEATURE_PLAN.md](UI_FEATURE_PLAN.md)。

## 1. 题目目标与范围

- 题目应服务于考研高等数学学习，明确对应章节或知识点。
- 每题聚焦一个主要考点；综合题应说明综合考查的内容。
- 题目应为原创题或经授权使用的题目。改编题应记录来源与授权状态，不得把来源不明的题目标为原创。
- 使用开放许可教材题目时，应在题目数据中记录教材、章节/题号、来源链接及完整许可；保留原题题干的中文转写或选择题化也属于改编，应遵守来源许可的署名、非商业和相同方式共享等条件。不得把仅供购买者练习的商业题库当成可自由转载来源。
- 难度标签使用“基础、强化、综合”，并与实际所需知识、推理长度和计算量相符。

## 2. 题干要求

- 使用完整、准确、无歧义的中文，交代必要条件、定义域、区间、参数范围、变量关系和所求对象。
- 题目条件必须足以确定答案；参数题需注明参数约束，极值题需明确区间及求最大值、最小值或最值。
- 不在题干中暗示答案，不使用无意义背景、含糊代词或“显然”等省略关键条件的表达。
- 题干中的数学符号、函数记号和变量含义前后一致。

## 3. 选择题选项与答案

- 默认提供四个互不重复的选项，且只有一个正确选项；若题型另有设计，须明确说明。
- 正确答案必须与题干、选项和解析完全一致。数据中的 `answer` 使用从 0 开始的选项索引：A 为 0、B 为 1、C 为 2、D 为 3。
- 错误选项应具有合理迷惑性，尽量对应常见概念或计算错误；不得出现多个等价正确项、遗漏正确答案、重复选项或量纲/表达格式不一致。
- 题干问“分别为”时，选项应按固定顺序给出对应量；题干问“以下正确的是”时，应保证正确项可唯一判定。

## 4. 标准解析结构

解析不能只给答案或一句结论。按题目需要写出以下内容：

1. **思路或依据**：指出使用的定理、定义、公式或关键观察；不需要冗长复述题干。
2. **关键推导**：按逻辑顺序展示变形、代入、分类讨论、变量替换、边界检查等必要步骤。
3. **计算与验证**：写清关键数值或表达式如何得到；容易漏检处（如端点、驻点、定义域、零解、雅可比因子）必须检查。
4. **结论**：明确写出最终答案，并与正确选项对应。

简短基础题可合并步骤，但必须让读者能从题目条件复现答案。禁止保留自我更正、草稿痕迹、问号式推理、相互矛盾的中间结论或未解释的跳步。

## 5. 数学公式与网页格式

- 行内数学公式使用 `$...$` 定界；避免在公式定界符内放不必要的中文句子。
- 题库 JavaScript 中含 LaTeX 的解析使用 `String.raw` 模板字符串，确保反斜杠原样传给 MathJax，例如：

  ```js
  explain: String.raw`<div class="solution-step">由 $e^x=1+x+\frac{x^2}{2}+o(x^2)$，得到……</div>`
  ```

- 不要把含 `\frac`、`\lim`、`\to`、`\partial` 等反斜杠命令直接写入普通 JavaScript 单引号/双引号字符串；也不要在输出前删除 `$` 定界符。
- 公式应采用规范记法，分数使用 `\frac{分子}{分母}`，上下标使用花括号，极限、积分和偏导符号按标准 LaTeX 书写。
- 公式必须经过页面公式引擎排版；不能接受原始 LaTeX 命令露出、`Math input error` 或公式吞掉标点的情况。
- 数学内容与 HTML 结构分开检查，新增 HTML 标签必须成对闭合；不要把用户输入拼入未经转义的 HTML。

## 6. 答案与解析的数学审核

每题加入题库前，由出题者完成一次独立复算，并逐项核对：

- 题干条件是否自洽，定义域及参数限制是否完整。
- 正确答案是否确实满足题意，其他选项是否均不满足。
- 解析每一步是否成立，使用定理时其条件是否满足。
- 特殊情形是否遗漏，包括端点、不可导点、零解、分母为零点及积分区域覆盖范围等。
- 解析最后的答案文字、选项内容与 `answer` 索引是否一致。

无法确定或仍有争议的题目不得伪装为已审核题；应先暂缓入库并标明待复核。

## 7. 题库字段约定

现有题目对象应至少保留以下字段，并确保含义一致：

```js
{
  topic: 0,                 // 对应 topics 数组的索引
  level: '基础',            // 基础 / 强化 / 综合
  type: 'choice',
  prompt: '题干',
  options: ['A项', 'B项', 'C项', 'D项'],
  answer: 0,                // 从 0 开始的正确选项索引
  hint: String.raw`不泄露完整结论的渐进提示`,
  explain: String.raw`分步解析与明确结论`,
  knowledge: '细分知识点'
}
```

- `topic` 必须指向有效专题；`answer` 必须在 `options` 有效范围内。
- 提示先引导观察或回忆方法，不直接复制完整解析、给出最终结果或泄露选项字母。具体提示写法见“提示规范”。
- `knowledge` 使用明确、具体、可复用的知识点名称。

## 8. 提示规范

- 每条提示都要让学生知道一个可以立即执行的下一步，例如先检查定义域、尝试某种变形、列出需要比较的点或回忆适用定理。
- 提示应针对当前题目的关键障碍，避免空泛鼓励、重复题干、直接复述解析或只说“仔细计算”“使用某某法则”。提到方法时还要指出它如何用于本题。
- 提示不得直接给出正确选项、最终数值、完整推导或解析结论；若提示分多级，按“观察方向 → 关键关系 → 方法提醒”逐级增加信息，最后一级仍不代替解析。
- 提示应简短完整、语气中性友好、标点规范。提示中的公式遵守本规范的 LaTeX 规则；页面如何重新排版由界面计划规范。
- 示例：推荐“把分子写成含有 $x$ 的因子与已知商的乘积，再分别考虑两个因子的极限。”；避免“答案是 0”或“用极限”。

## 9. 发布前核对清单

- [ ] 题干完整、无歧义，知识点与难度标签准确。
- [ ] 选项互异且唯一答案明确；答案索引对应正确选项。
- [ ] 解析有依据、有关键步骤、有明确结论，且与答案一致。
- [ ] 提示具体指导下一步，不泄露答案；提示中的公式能正确排版。
- [ ] 已独立复算，并检查题目涉及的特殊情形。
- [ ] LaTeX 反斜杠在题目数据中得到保留，公式语法完整。
- [ ] 题目数据中没有原始 LaTeX 命令或不完整公式标记。
- [ ] 题目来源与授权状态符合项目要求。
